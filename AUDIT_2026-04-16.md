# Deep End-to-End Audit

Date: 2026-04-16
Repo: `TikTok-Lyric-Video-Pipeline`
Branch at audit time: `adminpanel2`

This file is an execution-grade handoff brief for a follow-up agent. It treats the repo README, env examples, Docker config, AGENTS instructions, and the established admin-panel plan/design contract as the source of truth.

## Executive Summary

The project has three major classes of problems:

1. The TikTok OAuth and upload integration is broken by code-level interface mismatches. This is a true end-to-end blocker.
2. The runtime/configuration model is inconsistent across env, DB settings, and JSON config, which creates silent failures in operator-facing settings.
3. The frontend admin panel is not compliant with the design/preset contract. It is not pixel-perfect to `screens & code`, and it still hardcodes theme primitives that the plan explicitly forbids.

Additional operational gaps:

- The README local host-run path is inconsistent with the shipped `.env.example`.
- The frontend default build path currently relies on an internal Next.js compile-mode workaround with type/lint checks disabled.
- There is no migration system for the platform database.

Validation snapshot taken on 2026-04-16:

- `npm run build` in `apps/web` completed successfully, but only via a compile-mode wrapper and Next warned the build still needs `generate` or `generate-env` to be finalized.
- `where python` and `where py` both returned not found in this workstation environment, so Python runtime validation could not be executed here.

## E. Concrete Fixes and Patches

### [FUNC-01] Repair the TikTok client contract

- Files: `src/tiktok_platform_worker/engine.py`, `src/tiktok_platform_api/routers/platform.py`, `src/tiktok_platform/tiktok_api.py`
- Problem: OAuth/upload code paths call different APIs than the actual client exposes.
- Root cause: stale integration code survived after `TikTokApiClient` was simplified.
- Fix:
  - change every construction site to `TikTokApiClient(settings)`
  - remove `build_chunk_plan` import and call
  - replace `bundle.open_id` with `bundle.subject`
  - replace `bundle.scope` with `bundle.scopes`
  - call `init_direct_post(..., file_path=video_path, ...)`
  - call `init_inbox_upload(..., file_path=video_path)`
  - call `upload_file(upload_url, video_path)`
  - either add `code` to `TikTokApiError` or stop reading `exc.code`
- Validation:
  - `python -m tiktok_platform_worker.main --once`
  - pytest coverage for `/integrations/tiktok/callback`
  - mocked upload flow test
- Priority: P0

### [FUNC-02] Make settings mutations non-destructive and canonical

- Files: `src/tiktok_platform_api/routers/platform.py`, `apps/web/app/settings/page.js`
- Problem: pause/resume wipes unrelated settings; frontend mutates local resource state with the wrong response shape.
- Root cause: `set_setting` is being used with full replacement semantics in some routes and partial-merge expectations in others.
- Fix:
  - for `/pipeline/pause` and `/pipeline/resume`, load existing settings, merge `paused`, and persist the merged object
  - after TikTok disconnect/preferences changes, refetch `/integrations/tiktok/status` instead of mutating local state with partial payloads
  - add explicit server-side handling for clearing preferred privacy instead of dropping `null`
- Validation:
  - save custom pipeline settings
  - pause and resume
  - reload page
  - confirm values persist
- Priority: P0

### [FUNC-03] Wire operator-adjustable runtime settings into actual runtime behavior

- Files: `apps/web/app/settings/page.js`, `src/tiktok_platform_api/routers/platform.py`, `src/tiktok_platform_worker/engine.py`, `src/tiktok_platform_worker/adapters.py`
- Problem: the UI exposes settings that do not drive the worker, and displays env defaults instead of stored runtime state.
- Root cause: runtime config is split between DB settings and a static JSON file loaded once at worker startup.
- Fix:
  - choose one runtime source
  - fastest safe patch: use DB-backed pipeline settings for upload mode and throughput inside the worker loop
  - update `/pipeline/settings` to return stored upload mode as the current value
  - if throughput settings cannot be made live now, remove them from the UI
- Validation:
  - change upload mode and throughput in UI
  - confirm worker behavior changes without restart
- Priority: P0

### [FUNC-04] Make render/upload orchestration idempotent

- Files: `src/tiktok_platform_api/routers/platform.py`, `src/tiktok_platform_worker/engine.py`, `src/tiktok_platform/models.py`
- Problem: rerendering can create duplicate upload jobs for the same clip.
- Root cause: successful render always inserts a new `UploadJob` without checking existing active jobs.
- Fix:
  - before creating an `UploadJob`, query for an existing non-terminal upload job for the clip
  - reuse or update it instead of inserting another
  - consider a uniqueness rule around active upload jobs per clip
- Validation:
  - rerender the same clip twice
  - confirm only one active upload job exists afterward
- Priority: P0

### [FUNC-05] Schedule across the backlog, not one clip at a time

- Files: `src/tiktok_platform_worker/engine.py`, `src/tiktok_lyric_pipeline/stages/scheduling.py`
- Problem: worker scheduling does not satisfy the documented "spread uploads across the next day" behavior.
- Root cause: each clip is scheduled in isolation at render completion.
- Fix:
  - introduce a scheduler service that looks at all rendered/unassigned clips plus existing queued upload jobs
  - compute the next-day spread once
  - do not call `schedule_jobs` with a single clip inside `process_render_jobs`
- Validation:
  - render several clips in succession
  - inspect queued upload jobs
  - slots should distribute across the next day
- Priority: P1

### [FUNC-06] Renew or redesign job leases for long-running work

- Files: `src/tiktok_platform_worker/engine.py`
- Problem: fixed 10-minute render leases and 5-minute upload leases can expire mid-work.
- Root cause: there is no periodic lease extension while a worker is actively rendering/uploading.
- Fix:
  - add a helper that refreshes `lease_expires_at` during long operations
  - or increase lease duration and heartbeat from the render/upload loop
- Validation:
  - simulate a render/upload longer than the lease
  - confirm the job is not requeued while still active
- Priority: P1
